## [Unreleased]

### Added

- **The tool builder is served.** `MCP_BUILDER_ENABLED=true` now composes the builder in the API
  binary — its pinned egress, OAuth adapters, licence minter, source registry and
  binding-ensure service all come from the API's own settings — instead of refusing startup,
  and the reference's 20 `builder_*` MCP tools are registered for a tenant-level `mcp` licence
  with no binding (the tenant-author caller). The listed descriptions and input schemas are the
  reference's own FastMCP inventory; a member `mcp` licence and the platform tenant are refused,
  and the tools' error texts are the reference's `guard` mapping. With the flag off, nothing
  changes: both mounts keep answering the reference's `404`, and that licence stays `401`.

- **PDF text extraction for the three PDF-reading legal tools.** `src/pdf/` reproduces the
  reference's pypdf-based `pdf_text.py`: the visitor flush semantics, font decoding (named
  encodings, `/Differences`, `/ToUnicode`, Type0/Identity-H), the superscript and bracketed
  article rules, and `cut_article` for the ELI consolidated PDF. `legal_eli_act_text`,
  `legal_duw_document` and `legal_uokik_document` now return the document's text instead of a
  permanent refusal; a real published act is a checked-in parity fixture. The ELI path keeps the
  reference's parsed-PDF cache (eight paths, a day), and a crafted nesting depth is refused as
  the reference's `RecursionError` is, never by exhausting the stack.


- **One success log line per finished run**: `WorkerStore::finish` logs the run id, tenant,
  runtime and the status it actually wrote, so every finish path (the worker controller,
  recovery's interrupts, the external driver) has exactly one line; inputs, results and
  credentials stay in the database.

- **The platform authoring surface.** `/mcp/sources` (7 operations: create, list, get, update,
  rotate the write-only token, disable, enable), `/mcp/services` and `/mcp/operations`
  (14 operations: first-version create, append, list, inspect, validate, publish, disable, and
  the bounded OpenAPI 3.1 operation import), and `/mcp/credential-profiles` (3 operations). All
  of it sits behind the platform operator key and a second pool
  (`MCP_PLATFORM_DATABASE_URL`) that names the same database under the `mcp_platform` role; an
  unset pool answers `503 platform_authoring_unavailable`, exactly as the reference does.
- `src/sources/`: the destination guard (public HTTPS only, no address literal, no userinfo,
  an operator allow-list), AES-256-GCM sealing of a source's one stored token with the source
  id as associated data, the strict `SourceAuth` union and the tenant-URL rule, and the
  platform repository with its `mcp_source_events` trail.
- `tests/fixtures/phase5a/oracle.json`, generated by the pinned reference itself
  (`parity/tools/gen_phase5a_fixtures.py`): every guard verdict, every refusal message and
  every canonical source body is compared against the oracle rather than an assumption.

- **The external driver (`mcp-external-driver`).** Runs whose runtime is `n8n_workflow`,
  `fr_project` or `fr_command` are now driven by a Rust process instead of the archived Python
  one. It is the single writer of those runs: an at-most-once dispatch (the `dispatch` event is
  committed before the upstream call, and a run found `starting` with that event and no external
  reference is `interrupted`, never re-sent), a lease kept alive across a slow upstream answer,
  deadline and cancel handling through `cancelling`, one-shot `fr_command` answers replayed from
  the stored reference, and forwarding of answered task inputs back to fr.
- The n8n adapter (webhook start with a two-minute HS256 JWT, execution polling with a 4 MiB body
  cap, result extraction with a 64 KiB cap, an `unknown`-status counter) and the fr adapters (an
  HMAC-signed channel envelope, project start/poll/cancel, `projects.get`/`projects.close`, and a
  bounded project view).
- `tests/fixtures/phase3c/oracle.json`, generated by the pinned Python reference itself
  (`parity/tools/gen_phase3c_fixtures.py`), so every signature, JWT, channel envelope and bounded
  view is compared against the reference rather than an assumption.

### Fixed

- **A member's per-login care-bus licence gets an empty builtin scope**, exactly as the
  reference does (`scope.py:95`), instead of a 401. The builtin caller now derives its scope
  from the introspection's `app` and `subject_kind`, which travel on the principal; inferring it
  from the `svc:` shape of the subject would have granted a member the tenant's tools, and a
  payload with no `subject_kind` grants nothing.

  ignored 0`.

## [0.1.0] - 2026-11-14

First public release: the health surface and the MCP handshake, ported from the reference
implementation and verified against its OpenAPI document.

### Added

- Health endpoints `GET /health`, `/health/live`, `/health/ready` and `/api/health`, matching
  the reference implementation's responses.
- An MCP endpoint at `/mcp` over the streamable HTTP transport. `initialize` negotiates the
  protocol version; `tools/list` returns an empty catalog. The wire shape is stateless and
  SSE-framed, and `capabilities.tools.listChanged` is serialised as an explicit `false`, as the
  reference does.
- PostgreSQL pool and embedded migrations, with `DATABASE_MIGRATE_URL` for running migrations
  around a transaction-pooling connection pooler.
- OpenAPI document generation (`--print-openapi`) that reads no configuration and touches no
  database, so parity tooling can diff it in a bare workspace.
- The parity contract (`parity.toml`) pins the reference implementation and names, phase by
  phase, every operation that is not yet ported.

### Not yet

- The tool catalog, credential broker and execution worker. See the README's table.
